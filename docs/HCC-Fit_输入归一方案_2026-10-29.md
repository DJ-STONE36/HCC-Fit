## 0. 先回答“能不能按这个改”

能。而且这份交接表已经把最难的部分（**不能自动把肝癌归成 HCC**、否定/疑似/既往/冲突、原话不覆盖、未知不补造）写清楚了。当前软件差距在于：

| 现状 | 交接表要求 |
|---|---|
| 左侧直接填 6 个场景字段，填完就能跑 | 先自由输入 → 提取 → 归一 → 追问 → 确认，才能跑 |
| 没有逐字段的原话/来源/状态 | 每个字段保存原话、整理值、状态、来源片段、确认状态 |
| 关键词直接当字段值 | 必须识别否定、疑似、既往史、患者主体、时间、冲突 |
| `patient_summary_zh` 一坨文本 | 疾病/治疗/阶段/结局/起点/范围/资料拆成独立字段 |
| 没有“不知道”选项 | 追问必须允许“不知道”，未知不能补造 |
| 无输入版本/审计 | 输入 ID、版本、时间、确认状态 |

**需要新增一个输入层，而不是改 Agent。** 现有 `Planner`/`HccPlanner` 只接收最终 `scenario`，所以只要在调用前把“确认后的场景卡”填进去，Agent v0.6 一行都不用改。

## 0.1 口径修订（2026-10-29）：场景只有一个自由输入

**场景区只保留一个输入框**，医生把患者情况、治疗、阶段、想问的问题写在一段话里；不再让医生分别填“病人情况 / 问题 / 时点 / 结局 / 已有资料 / 缺失资料”六个字段。

```
┌──────────────────────────────────────────────────────────┐
│ 请描述患者情况和你想回答的问题（一段话即可）              │
│ [58岁男性，乙肝，肝癌，刚做完切除，病理没出来，          │
│  想看看三年生存率……]                              [解析] │
└──────────────────────────────────────────────────────────┘
```

- **场景卡是解析结果，不是第二个输入**：医生只在卡上确认/纠正；
- 六个字段在界面上隐藏，内部由场景卡映射成 Agent v0.6 的 `scenario`；
- 论文上传 / 关键段落是**文献输入**，不属于“场景字段”，保持不变；
- 一段话里缺少关键信息 → 集中追问，**不是**让医生回去补六个框。

内部映射（确认后自动完成，医生不用手填）：

| 场景卡字段 | Agent v0.6 的 `scenario` |
|---|---|
| 疾病 + 治疗 + 阶段 + 人群/资料 | `patient_summary_zh`（由确认字段拼成通顺摘要，原话另存） |
| 预测需求 / 想问的问题 | `task_zh`（若原话没问，追问后生成） |
| 当前阶段 / 预测起点 | `use_timepoint`（映射为 `pre_surgery` / `post_surgery` 等） |
| 预测结局 + 范围 | `outcome_type`（如“3 年总生存”） |
| 已有资料 | `inputs_given` |
| 缺失/未取得 | `inputs_missing` |

> 原则：**医生只写一段话**；系统负责拆字段、补问、拼摘要。原话始终保留在 `input_session.raw_text`。

## 1. 目标流程

```
医生自由输入（一段话，可多句）
   │
   ▼
① 提取候选（AI 可选 / 规则基线）
   │  疾病、治疗、当前阶段、预测结局、预测起点、时间范围、更新意图、已有资料
   ▼
② 术语归一（项目内标签，不是官方编码）
   │  同义词合并；上位词不强行细分；肝癌/肝脏肿瘤/恶性肿瘤 ≠ HCC
   ▼
③ 语境检查
   │  否定、疑似、既往史、患者主体、时间、前后句冲突
   ▼
④ 集中追问（只问影响启动的关键项，允许“不知道”）
   ▼
⑤ 可编辑场景卡（原话 / 整理值 / 状态 / 来源 / 确认）
   ▼
⑥ 医生确认（或逐项修改）
   ▼
⑦ 冻结 `input_session`（input_id + 版本 + 确认状态）
   ▼
⑧ 交给现有 Planner / Agent v0.6 做检索核查
```

**关键闸门**：第 ⑦ 步未确认，不进入核查。未支持/未明确的场景，明确说明限制，不伪造正式结论。

## 2. 数据模型（每个字段都存这 5 样）

```json
{
  "input_id": "in_20261029_a1b2c3",
  "version": 1,
  "created_at": "2026-10-29T13:30:00+08:00",
  "raw_text": "肝癌患者，刚切完，病理还没出来，想看看三年生存。",
  "fields": {
    "disease": {
      "raw": "肝癌患者",
      "normalized": "肝脏恶性肿瘤，类型未明确",
      "status": "ambiguous",
      "source_span": [0, 4],
      "source_sentence": "肝癌患者，刚切完，病理还没出来，想看看三年生存。",
      "confirm": "pending",
      "candidates": [
        {"value": "肝脏恶性肿瘤，类型未明确", "rule": "UPPER_TERM_NO_HCC"}
      ],
      "flags": ["类型未明确", "不得自动归为HCC"]
    },
    "treatment": { "...": "..." },
    "stage": { "...": "..." },
    "outcome": { "...": "..." },
    "start_point": { "...": "..." },
    "horizon": { "...": "..." },
    "intent": { "...": "..." },
    "data_available": [
      {"raw": "病理还没出来", "normalized": "病理未取得", "status": "normalized",
       "source_span": [9, 15], "confirm": "user_confirmed"}
    ]
  },
  "conflicts": [
    {"field": "treatment", "spans": [[0, 3], [20, 28]],
     "message": "前句称未手术，后句称已术后"}
  ],
  "followups": [
    {"id": "q_disease", "field": "disease", "required": true,
     "question": "请确认是 HCC、其他类型，还是尚未明确？",
     "options": ["HCC", "其他类型", "尚未明确", "不知道"]}
  ],
  "confirmation": {"status": "pending", "confirmed_at": null}
}
```

**字段状态枚举**（与交接表对齐）：

| status | 含义 |
|---|---|
| `normalized` | 明确同义词已归一到项目标签 |
| `ambiguous` | 上位词/类型未明确（如“肝癌”“恶性肿瘤”） |
| `suspected` | 疑似/考虑/待排（如“疑似 HCC”） |
| `negated` | 否定（如“非 HCC”“已排除 HCC”） |
| `historical` | 既往史，不等于本次诊断 |
| `conflict` | 前后句/字段冲突，未自动覆盖 |
| `unknown` | 未提供/无法确认 |
| `out_of_scope` | 非首版 HCC 范围（iCCA、肝转移等） |
| `confirmed` | 医生已确认（配合 confirm 字段） |

**确认状态**（独立于 status）：`pending` / `user_confirmed` / `user_edited` / `user_unknown`。

> 原话只在 `raw` 和 `raw_text` 里保存，**任何归一/修改都不覆盖原话**；`normalized` 是独立字段。

## 3. 术语规则（按交接表 01）

| 原始表达 | 项目内标签 | 处理 | 追问 |
|---|---|---|---|
| 肝细胞癌 / HCC / hepatocellular carcinoma | **HCC** | 同义归一；检查否定/疑似语境 | 明确诊断才记为“用户陈述”，不等于系统确诊 |
| 肝癌 / 原发性肝癌 | **肝脏恶性肿瘤，类型未明确** | **不自动归为 HCC** | 请确认 HCC / 其他类型 / 尚未明确 |
| 肝脏肿瘤 / 肝占位 | **肝脏病变，性质与类型未明确** | 保留未知 | 是否已明确诊断；不判断良恶性 |
| 恶性肿瘤 | **恶性肿瘤，部位及类型未明确** | 不自动补为肝癌 | 请确认部位和类型 |
| 肝内胆管癌 / iCCA | **肝内胆管癌** | 识别为**非首版 HCC 范围** | 不转换为 HCC；说明范围限制 |
| 结肠癌肝转移 | **肝转移性病变** | 不归 HCC | 说明首版范围限制 |
| 考虑 HCC / 疑似 HCC / HCC 待排 | **HCC 疑似** | 保留疑似修饰 | 不能标为确诊；诊断状态影响后续核查 |
| 非 HCC / 已排除 HCC | **HCC 被否定** | 保留否定 | 不能因含 HCC 字样提取为阳性 |
| 既往 HCC，本次病灶未定 | **HCC 既往史；当前病灶未定** | 历史与当前分开 | 不将历史诊断当本次诊断 |
| 有血管侵犯 / 有癌栓 | **血管侵犯类型未明确** | 不自动映射宏血管侵犯或 MVI | 候选模型明确后追问影像/病理来源与定义 |
| MVI / 微血管侵犯 | **微血管侵犯** | 同义归一，保留阳性/阴性/未知 | 具体分级与来源按论文核对 |
| 术后 | **治疗后，治疗类型未明确** | 追问什么治疗、是否完成 | 不自动推定肝切除、R0、病理已出 |
| 术后三年 | **时间含义未明** | 区分“已术后三年”与“预测术后三年” | 不单凭这几个字设预测范围 |
| 看预后 / 还能活多久 | **预测需求未明确** | 澄清结局、起点、范围 | 不直接生成寿命或概率 |

**硬规则（必须写进代码测试）**：

1. `肝癌`、`肝脏肿瘤`、`恶性肿瘤` **永远不自动映射为 HCC**；
2. HCC 只能来自明确的 `HCC/肝细胞癌/hepatocellular carcinoma`，或医生在场景卡里确认；
3. `疑似/考虑/待排` 不能当确诊；
4. `非/排除/无` 不能被关键词当成阳性；
5. `既往` 不能当本次；
6. 没有提到 ≠ 阴性（如“没有 MVI 结果” → `unknown`，不是 `negative`）；
7. 冲突不覆盖，列出来问医生。

## 4. 提取实现：规则基线 + AI 候选（推荐）

交接表说“AI 提出提取候选；字典与结构校验约束；临床负责人审核语义规则”。建议分两层：

### 4.1 规则基线（v0.1 必须有，离线、可审计）

- 术语词典：`resources/terms.csv`（概念、同义词、上位词、是否允许自动归一、范围）；
- 分句：按 `。！？；\n` 切句，保留字符偏移；
- 上下文窗口：匹配词前后各 8–12 字，识别：
  - 否定：`非/不是/排除/未见/无/否认`
  - 疑似：`疑似/考虑/待排/可能/不除外`
  - 既往：`既往/曾/以前/病史`
  - 主体：`患者/我/家属/父亲/母亲`（主体不是患者要单独标记）
  - 时间：`术前/术后/刚/今天/三年/36个月/两年`
- 同一字段多个候选且语义冲突 → `conflict`，不选一个；
- 每个结果带 `source_span` 和 `source_sentence`；
- 不用模型概率决定医学事实；规则命中即给出状态，拿不准就 `unknown`。

### 4.2 AI 候选（可选，v0.2）

- 接口：`ExtractionProvider.extract(raw_text) -> [FieldCandidate]`；
- 默认 `RuleExtractor`；可选 `LLMExtractor`（独立 prompt，**不调用/不修改 Agent v0.6**）；
- AI 只给候选值和 span；最终 status 由规则/字典/医生确认决定；
- 无 Key/无网络时自动退回规则基线，不影响使用。

> 这样既满足“不要只做关键词替换”（有上下文、否定、疑似、历史、冲突），又不把医学事实交给模型自报概率。

## 5. 集中追问（只问关键项）

追问优先级（只问阻塞启动的）：

1. **疾病类型**：HCC / 其他类型 / 尚未明确（`肝癌/恶性肿瘤` 必问）；
2. **治疗与阶段**：做了什么治疗、是否完成、病理是否取得（`术后` 必问）；
3. **预测起点**：从手术日 / 从今天 / 其他（`术后三年` 必问）；
4. **预测结局与范围**：OS / 复发 / 其他；时间范围（`三年生存` 必问）；
5. **冲突项**：前后句矛盾，必须选一个；
6. **患者主体**：是患者本人还是家属。

UI 形态：

- 一句集中问句（交接表 03 的写法），下面给选项 + “不知道” + 自定义；
- “不知道”是合法答案，记为 `user_unknown`，不补造；
- 模型专用指标（影像组学、MVI 分级等）**不在首屏全部索取**，等候选模型明确后再问。

## 6. 场景卡 UI（PySide6）

主界面的“场景”区改成一个自由输入框 + 场景卡（不再是六个字段）；论文上传区不变：

```
┌────────────────────────────────────────────────────────────┐
│ 1 自由输入                                                  │
│ [肝癌患者，刚切完，病理还没出来，想看看三年生存。]  [解析]   │
├────────────────────────────────────────────────────────────┤
│ 2 场景卡（可编辑）                                          │
│ 字段    原话        整理值              状态      来源  确认 │
│ 疾病    肝癌患者    肝脏恶性肿瘤，类型未明确  ⚠待确认  句1  [改]│
│ 治疗    刚切完      治疗后，治疗类型未明确    ⚠待确认  句1  [改]│
│ 阶段    病理还没出来 治疗后，病理未取得       ✅已归一  句1  [改]│
│ 结局    三年生存    候选：总生存 OS          ⚠待确认  句1  [改]│
│ 起点    未说        未明确                   ❓未知     —    [改]│
│ 范围    三年        36 个月                  ✅已归一  句1  [改]│
├────────────────────────────────────────────────────────────┤
│ 3 集中追问                                                  │
│ 请确认：① HCC/其他/未明确 ② 切除类型 ③ 从手术日还是今天算？  │
│ [HCC] [其他] [尚未明确] [不知道]                             │
├────────────────────────────────────────────────────────────┤
│ [重新解析] [保存草稿]              [确认场景卡，进入核查]     │
└────────────────────────────────────────────────────────────┘
```

- 状态颜色：✅ 已归一 / ⚠ 待确认 / ❓ 未知 / ❌ 否定 / 🕘 既往 / ⚡ 冲突 / ⛔ 超范围；
- 每行可展开看原句 + 字符位置；
- 医生修改 → `confirm=user_edited`，版本 +1；
- 确认 → `confirm=user_confirmed`，冻结输入；
- 未确认 → “进入核查”按钮禁用；
- 保存草稿 → `input_sessions/<input_id>.json`；
- 确认后把字段映射为现有 `scenario`，再调用现有 `Planner/HccPlanner`。

## 8. 验收用例（直接来自交接表 04）

| 输入 | 期望 |
|---|---|
| `HCC，准备肝切除，预测从手术日起一年复发` | 识别 HCC 和术前意图；不要求已有术后病理；具体输入完整性未知 |
| `疑似 HCC，未治疗，想看预后` | 疑似不改确诊；澄清结局及时间；不输出诊断 |
| `肝内胆管癌术后，想看三年 OS` | 不映射为 HCC；说明首版范围 |
| `没有 MVI 结果` | 记录 MVI 未知/未取得，不记录阴性 |
| `术后两年，问未来三年生存` | 分别记录当前已术后两年与从当前起三年需求；识别更新需求，不改手术日起三年 |
| `前句称未手术，后句称已术后` | 显示冲突，请用户确认，不任意选一句 |
| `肝癌患者` / `肝脏肿瘤` / `恶性肿瘤` | **不得自动归为 HCC**；类型/部位未明确，追问 |
| `非 HCC` / `疑似 HCC` / `既往 HCC` | 否定/疑似/既往状态正确，不误当阳性 |
| 任意输入 | 每字段有原话、整理值、状态、来源片段、确认状态；原话未被覆盖；未知未补造 |

补充自动化测试：

- 术语表逐行断言（含“肝癌≠HCC”）；
- 否定/疑似/既往窗口测试；
- 冲突检测测试；
- 场景卡确认门禁测试（未确认不能运行）；
- 原话/来源 span 与原文逐字一致；
- 保存/重载 input_session 版本一致。

## 10. 风险与需要确认

| 风险 | 对策 |
|---|---|
| 中文自由文本歧义多 | 规则只做“可解释的候选”，拿不准一律 `unknown` + 追问 |
| 否定/疑似窗口误判 | 分句 + 前后窗口 + 测试集；临床审核 |
| 把“肝癌”归成 HCC | 硬编码禁止 + 单测锁死（这是最高优先级） |
| 冲突被自动覆盖 | 冲突字段不选值，只列出来问 |
| 患者主体（家属） | 识别“我/患者/家属/父亲”等，主体不明时追问 |
| 时间语义（术后三年） | 拆成“当前已术后时长”和“预测范围”两个字段 |
| AI 候选不稳定 | AI 只提候选，规则/字典/医生确认决定状态；无 Key 退回规则 |
| 术语表谁维护 | 临床负责人审核；版本化 `terms.csv`，变更记 changelog |
| 不修改 Agent v0.6 | 输入层独立；`git diff` 只允许输入层/UI/资源文件 |

需要确认：

1. 首版提取用**纯规则**，还是**规则 + LLM 候选**？（建议规则先行，LLM 可选）
2. 术语表由谁最终审核？（临床负责人）
3. 场景卡确认后是否还允许修改？建议：修改需重新确认，版本 +1；
4. 输入会话保存多久？是否需要导出给审计？
5. “患者主体”首版是否必须识别（家属代问）？
