## 0. 结论摘要（先看这段）

**总体判断：链路是真的、工程纪律是好的，但"能跑"和"可相信"之间还差两个必修项。**

| 维度 | 评价 | 依据 |
|---|---|---|
| 核心链路完整性 | **好** | S0–S4 五阶段、4 种大脑、SSE 进度、落盘恢复全部实测可跑 |
| 自动化测试 | **好** | 四条自测在可写目录下 **31/31 全绿**（8+8+5+10） |

## 4. 缺陷清单

### 4.1 严重（必须先修）

#### D1 · `unknown` 被归一成 `mismatch` —— 直接反转产品核心语义

> ✅ 2026-10-28 已修复（见附录 E）：`unknown` / `not reported` / `no data` 现在稳定归一为 `unknown`，并补了回归测试。

**位置**：`contract.py:20`（关键词表）、`contract.py:80-86`（`_status`）

```python
"mismatch": ["mismatch", "不匹配", "不符", "不一致", "冲突", "对不上", "no", "false", "否"],
...
for canon in ("mismatch", "unknown", "match"):
    if any(w.lower() in s for w in STATUS_MAP[canon]):
        return canon
```

`"unknown"` 含有子串 `"no"`，而 `mismatch` 优先匹配，于是：

```
_status('unknown')            -> 'mismatch'   ← 应为 unknown
_status('not reported')       -> 'mismatch'
_status('no data')            -> 'mismatch'
_status('unknown (missing)')  -> 'mismatch'
```

**实测影响（端到端）**：mock 平台的 `input` 维度明确返回 `"status": "unknown"`，落盘的 `visit.json` 变成：

```
('input', 'mismatch', '需要 4 项影像组学特征，当前未产出（mock）')
uncertainties: ['本次未记录到显式不确定项，但仍需人工复核论文结论与适用边界。']
```

即：**"无法确认"在界面上变成红色"不匹配"，同时"我们不确定的事"里也不再列出这一项**——把"资料不足"说成了"结论相反"，还少报了一条不确定性。
更讽刺的是：`sciencepal.py` 的阶段骨架里明确要求模型输出 `match|mismatch|unknown`（`sciencepal.py:654`），也就是说**按提示词正确作答的模型，必然踩这个坑**。

**连带问题（同一处关键词匹配过宽）**：

- `normalize_papers` 的 `decision` 含 `"no"` → 论文 `decision="unknown"` 被判为 **exclude**（实测）；
- `_conf("不高")` → **high**（实测，`"高"` 子串命中）。

**建议**：先做精确取值归一（`unknown/uncertain/未报告/…` → unknown），再做**词边界**匹配；删除 `"no"/"false"/"否"` 这类过短词，或改成整串相等；`mismatch` 与 `unknown` 的判定顺序改为"未知优先"。补三条回归断言：`_status("unknown")=="unknown"`、`_status("not reported")=="unknown"`、`normalize_papers(decision="unknown")["decision"]!="exclude"`。

#### D2 · `/api/upload` 的 `sid` 未净化 → 任意路径写文件

> ✅ 2026-10-28 已修复（见附录 E）：`sid` 走白名单 + 路径包含校验，穿越请求返回 400；`/api/files`、`/files/*`、`/api/log`、`/api/result` 同步加了校验；CORS 从 `*` 收紧为仅回显本机来源。

**位置**：`server.py:255-264`

```python
sid = fields.get("sid") or new_sid()
fdir = os.path.join(WORKSPACES, sid, "files")
os.makedirs(fdir, exist_ok=True)
...
with open(target, "wb") as fh:      # target 完全由 sid + 文件名决定
```

**实测**：提交 `sid = "..\..\_pwn"`、文件名 `pwned.txt`，文件被写到

```
D:\HCC-Fit\<临时副本>\_pwn\files\pwned.txt      （workspaces 之外；副本已清理）
```

即 **workspaces 之外**。同名文件会被静默覆盖，因此可覆盖任意可写文件（包括 `server.py` 自身）。

**放大因素**：

- `Access-Control-Allow-Origin: *`（`server.py:161`），而 `multipart/form-data` 属于"简单请求"，**不需要预检**；
- 服务无任何令牌/鉴权。

→ 用户浏览任意恶意网页时，该页面即可向 `127.0.0.1:8848` 写文件。虽然是本机单用户工具，仍应视为高危。

**建议**：`sid = re.sub(r"[^A-Za-z0-9._-]", "", sid)[:40]`，并用 `os.path.realpath` 校验 `target` 必须位于 `WORKSPACES` 之下；CORS 改为同源或删除该头；上传增加随机前缀防覆盖。

### 4.2 中等（影响可用性或与宣称不符）

#### D3 · "查看 Agent 原始返回"抽屉从未实现

- `index.html:138-141` 有 `<details id="raw" class="rawbox hidden">` 与 `#raw-body`；
- `static/app.js` 全文没有引用 `#raw` / `#raw-body`（grep 确认），`hidden` 永远不会移除；
- 数据其实齐全：`visit.raw_answers`（每阶段原话，SciencePal/mock 模式实测 5 条）与 `raw_excerpts` 都在。

→ 违反交接文档硬约束 #2「原始返回永远可查看」，也违反 README §2 对第 5 区的描述。用户唯一能看到原文的途径是下载 `visit.json` 后自己翻。

#### D4 · `text_fallback` 黄色横幅从未实现，降级事件前端不处理

- `index.html:118` 有 `#fallback`，`style.css:133-136` 有 `.fallback`，但 `app.js` 无引用；
- `planner.py:95-96` 会发 `status="degraded"` 事件，`app.js:83-94` 的 `markStage` 只处理 `start/ok/pending/error`，该事件被静默忽略；
- 副作用：`app.js:120` 在无方案时提示"请见上方原文摘要"，但**页面上并不存在这个区块**（指针指向空气）。

→ 违反硬约束 #4「降级必须显式」。实际上降级后用户只看到结论变成一段原文 + "没有结构化方案"，没有任何警告，容易被误读为正常结论。

#### D5 · `cautions_zh`（注意点）采集了但从不显示

schema 必填、stub 提供 3 条（含"演示数据，不是真实论文结论""不构成诊断或治疗建议"），mock 提供 2 条；`app.js` 全文无 `cautions`。
→ 这是**安全相关信息的丢失**，优先级应高于普通展示项。

#### D6 · `quote`/`location` 从不显示，证据不可核对

- `contract.py` 会保留 `quote`/`location`（mock 实测四维都有引文）；

## 5. 与 PACK 规范的差距（重要）

PACK 的定位是"判定在代码里、证据可核对"的通用核查机；APP 的定位是"让 LLM 逐阶段给 JSON、前端渲染"。两者是**两套并行的实现**，不是同一套内核 + 前端：

| 不变式 | PACK 要求 | APP 现状 |
|---|---|---|
| I1 证据绑定 | 每个非空结论必须有 `{quote, location}` 且能逐字核对 | 字段采集了，但**从不校验、从不显示**；`check_quotes.py` 未接入 |
| I2 三值逻辑 | `unknown` 是一等公民 | **被 D1 破坏**：显式 `unknown` → `mismatch` |
| I3 判定确定性 | 判定在代码里，同输入同输出 | 判定完全由 LLM 输出；stub 确定性，真机不确定；无温度/种子/哈希 |
| I4 可弃答 | 证据不足必须弃答 + 给缺口 | 有 `unknown`/`uncertainties` 结构，但 D1 使其失效；域外仍会继续跑完 S1–S4 |
| I5 可审计 | 版本三元组 + 输入哈希 + manifest + trace | 仅 `provenance` 四个字段；无输入哈希、无版本三元组、无 manifest |
| I7 合规 | 不诊断、不推荐、不碰 PHI | 免责声明与 cautions 有（但 cautions 不显示）；**无 PHI 闸门**；提示词只在 integrate 阶段说"不要给治疗建议" |

另外，APP 的产物 `visit.json` 与 PACK 的 `report.schema.json` **结构完全不同**，PACK 的 `validate_output.py` / `check_quotes.py` / `conformance_ui.py` 无法直接校验 APP 的产物。交接文档说 PACK"留着查背景"是诚实的，但如果目标是按 PACK 提交，APP 目前不能作为其前端。

## 附录 C · `start.bat` 修复记录（2026-10-28）

**症状**：双击 `start.bat` 后窗口闪一下就没了，或只看到 `命令语法不正确`（退出码 255），服务根本没起来。

**根因 1（致命，任何机器都会复现）**：原 `start.bat` 是 **LF 换行**（0 个 CRLF，25 个 LF），CMD 解析 `if %errorlevel%==0 (` 这类括号块时失败。对照实验：

| 文件 | 结果 |
|---|---|
| 原文件原样（LF） | `命令语法不正确`，退出码 255 |
| 同一内容改为 CRLF | 正常走到 `python server.py` |

**根因 2（次要，缺 Python 时才触发）**：原文件 `echo ... "Add python.exe to PATH"，然后...` 这种“中文 + ASCII 引号”的行，在 CMD 的 UTF-8 代码页下会被拆坏，出现 `'选' is not recognized`。

**修复内容**（`HCCFIT_APP/start.bat`，1,473 字节，55 个 CRLF，纯 ASCII）：

1. 全文改为 **CRLF + ASCII**，彻底避开 CMD 的编码/换行解析问题（网页界面仍是中文，只有启动器消息改成英文）；
2. Python 探测改为**版本校验** `sys.version_info >= (3,9)`，避免 `python` 是 Microsoft Store 别名或 Python 2；
3. `workspaces` 改用 `if not exist "workspaces\"` 判定目录，创建失败时给出明确提示；
4. 增加 8848 端口占用提示；
5. 失败时 `pause`，窗口不再一闪而过；
6. 删除硬编码的他人路径 `C:\Users\weize jie\...`。

**验证**：

- 可写目录下双击/命令行启动 → `/api/health` 200、首页 200；
- `PATH` 中无 Python → 正确打印 `[X] Python 3.9+ was not found.`；
- 把 `workspaces` 替换成同名文件制造不可写 → 正确打印 `[X] Cannot create the "workspaces" folder here...`。

**仍存在的环境问题**：`server.py` 没有 `--data-dir` 参数；若整个 `HCCFIT_APP` 放在只读目录（Program Files、只读共享、某些沙箱工作区），`os.makedirs(WORKSPACES)` 仍会抛 `PermissionError`。临时办法是把文件夹复制到桌面/文档再运行；要根治可给 `server.py` 增加 `--data-dir` 或 `HCCFIT_WORKSPACES` 环境变量回退（约 5 行改动）。

## 附录 E · D1 / D2 修复记录（2026-10-28）

### E1 · `unknown` 不再被误判成 `mismatch`

**原因**：`STATUS_MAP["mismatch"]` 里放了 `"no"`，而 `"unknown"` 含子串 `"no"`；`_status` 又先判 `mismatch`，于是显式 `unknown` 全部变成 `mismatch`，`uncertainties` 也跟着漏报。

**改法**（`contract.py`）：

- `mismatch` 子串表删掉 `"no" / "false" / "否"`，只保留 `mismatch / 不匹配 / 不符 / 不一致 / 不是 / 冲突 / 对不上`；
- 新增 `EXACT_STATUS`：只有整串等于 `no/false/否/不是` 才算 mismatch，`yes/true/是` 才算 match；
- `unknown` 词表补充 `not reported / no data / missing / 未报告 / 未给出 / 资料不足`；
- `_status` 先精确匹配、再按 `mismatch → unknown → match` 子串匹配；
- `_conf` 先判 `不高/低/low/weak` 再判 `高`，修掉 `不高 → high`；
- `normalize_papers` 的纳入判断改用 `exclude/排除/不纳入/拒绝/reject/not include`，`decision=unknown` 不再被误排除。

| 输入 | 修复前 | 修复后 |
|---|---|---|
| `unknown` | mismatch | **unknown** |
| `not reported` / `no data` | mismatch | **unknown** |
| `unknown (data missing)` | mismatch | **unknown** |
| `不匹配` / `mismatch` | mismatch | mismatch |
| `匹配` / `match` | match | match |
| `不高`（置信度） | high | **low** |
| `decision=unknown` | exclude | **include** |

**验证**：mock 五阶段产出的 `input` 维度保持 `unknown`，且 `uncertainties` 出现「论文 p1 的「input」无法确认…」。

### E2 · `sid` 路径穿越已封堵，CORS 已收紧

**改法**（`server.py`）：

- 新增 `safe_sid()`：只允许 `[A-Za-z0-9][A-Za-z0-9._-]{0,63}`，且拒绝含 `..` 的值；
- `POST /api/upload`：非法 `sid` 直接 400；落盘前再做 `realpath` 包含校验，确保目录在 `workspaces` 之下；
- `POST /api/run`：非法 `sid` 返回 400（不再拿它拼工作区路径）；
- `GET /api/files`、`GET /files/<sid>/<name>`、`GET /api/log`：`sid` 一律走 `safe_sid`；
