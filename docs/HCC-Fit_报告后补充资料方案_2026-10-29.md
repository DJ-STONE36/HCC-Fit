# HCC-Fit 报告后补充资料 / 重新分析方案（v0.1，2026-10-29）

> 目标：报告给出“还缺什么数据”后，医生可以在结果页直接补一段资料，重新提交给同一个 Agent 分析；
> 原报告保留，新报告可对比；**不修改 HCC-Fit Agent v0.6**。
>
> **2026-10-29 修订**：按用户要求，“所需资料”改为一个只读文本框（自动换行、无横向滚动），
> 每一条缺失资料下面对应一个输入框；不再是单个大输入框。
>
> **P0–P2 已落地（2026-10-29）**：`app/supplement.py`、`supplement_store.py`、结果页“补充资料”页签、全量重跑、新旧报告切换、`tests/test_supplement.py`（3/3）、`tests/test_supplement_ui.py`（5 次重复通过）均完成；exe 已重新打包。

---

## 1. 结论

可以做，建议做成**报告后的“补充资料”页签**：

```
报告 → 看到“还缺什么数据” → 在补充输入框写一段补充资料
     → 点“重新提交分析” → 用原场景 + 补充资料重跑
     → 生成新报告（parent_visit_id 指向旧报告）
```

首版：上方用**一个只读文本框**显示报告缺失项；下面**每条缺失项对应一个输入框**，医生按项填，不要求一段话全写。

---

## 2. 为什么不改 Agent v0.6

Agent 只接收 `scenario`。补充资料可以作为：

- `scenario.patient_summary_zh` 追加“报告后补充资料：……”
- `scenario.inputs_given` 追加“报告后补充：……”
- `scenario.inputs_missing` 保留原缺失项（不假装已补齐）

然后用现有 `RunWorker` / `Planner` / `sciencepal_hcc` 原样重跑。**`sciencepal.py`、`planner.py`、`hcc_report.py`、`visit.schema.json` 都不改。**

首版不做“只把增量发给 Agent”的增量调用；因为 Agent v0.6 的提示词与产物契约固定，增量调用需要改 prompt/解析，风险大。全量重跑虽然多花一次时间，但结果可复现、可对比。

## 3. 界面（结果页新增“补充资料”页签）

```
┌──────────────────────────────────────────────────────────────┐
│ 5 · 就诊反馈   [结论] [四维] [论文/方案/期望] [原始返回] [补充资料] │
├──────────────────────────────────────────────────────────────┤
│ 报告认为还缺这些（来自 expected_data）                         │
│  • 动脉期影像组学特征（4 项）   [ ] 已补                        │
│  • 病理分级 / MVI              [ ] 已补                        │
│  • 术后具体时间                 [ ] 已补                        │
│                                                              │
│ 补充资料（检查/病理/参数/时间，一段话即可）                     │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │ 例：2026-10-28 增强 CT：动脉期环形强化，包膜完整；        │ │
│ │ 病理：中分化 HCC，MVI 阴性；手术日期 2026-10-20。         │ │
│ └──────────────────────────────────────────────────────────┘ │
│                                                              │
│ [保存草稿]                         [重新提交分析]              │
└──────────────────────────────────────────────────────────────┘
```

要点：

- 上方“所需资料”是一个只读文本框（自动换行、无横向滚动）；
- 下方每条缺失项对应一个输入框，一一对应；
- 上方 `expected_data` 只读展示，带“已补”勾选（仅用于记录，不自动解析）；
- “重新提交分析”需要至少输入 10 个字符，否则禁用；
- 提交前弹确认：
  > 将作为一次新的核查提交，原报告保留；预计需要 3–5 分钟。
- 新报告出来后：
  - 顶部显示“本次为补充后报告（基于 visit_xxx）”；
  - 可切换“上一次报告 / 本次报告”对比；
  - 原报告仍可导出 PDF/JSON。

## 4. 数据模型

新增 `supplement` 记录，与原 `visit` 分开存：

```json
{
  "supplement_id": "sup_20261029_a1b2c3",
  "parent_visit_id": "visit_1793250000",
  "parent_input_id": "in_20261029_xxx",
  "created_at": "2026-10-29T14:30:00+08:00",
  "raw_text": "2026-10-28 增强 CT：动脉期环形强化……",
  "expected_items": [
    {"item_zh": "动脉期影像组学特征（4 项）", "checked": true},
    {"item_zh": "病理分级 / MVI", "checked": true}
  ],
  "applied": true,
  "new_visit_id": "visit_1793250300"
}
```

存到：

```
AppLocalData/supplements/<supplement_id>.json
```

- 原 `visit.json` 不改；
- `visit.schema.json` 不改；
- 审计时用 `supplement_id` / `parent_visit_id` 关联；
- 导出 JSON 仍是原 `visit.json`，补充记录另存。

## 5. 提交时如何拼 scenario

```python
def build_supplemented_scenario(visit, supplement_text):
    sc = dict(visit["scenario"])          # 原场景
    add = supplement_text.strip()
    sc["patient_summary_zh"] = (
        sc.get("patient_summary_zh", "")
        + "\n\n【报告后补充资料】\n" + add
    )
    sc["inputs_given"] = (
        (sc.get("inputs_given") or "")
        + ("；" if sc.get("inputs_given") else "")
        + "报告后补充：" + add
    )
    # inputs_missing 保持原样：不因为医生写了一段话就假装已补齐
    return sc
```

原则：

- **只追加用户原文**，不自动把“MVI 阴性”等解释成结构化字段（避免误读）；
- 不改 `task_zh` / `use_timepoint` / `outcome_type`；
- 如果补充资料实际上改变了疾病/治疗/时点（例如病理确诊 HCC、改术式），应回到“场景卡”重新确认，而不是只走补充框；
- 补充文本长度截断到 4000 字符，防止 prompt 过长；
- 原 `inputs_missing` 保留，方便 Agent 继续指出“仍未补”。

## 6. 重跑流程

```
点“重新提交分析”
  ├─ 校验：有补充文本 + 当前没有运行中的任务
  ├─ 生成 supplement_id
  ├─ 新 workspace（新 sid），复制同样的论文/附件
  ├─ 拼 scenario（原场景 + 补充文本）
  ├─ 复用现有 RunWorker(mode, ws, scenario, files, opts)
  ├─ 写入 supplement.json（parent_visit_id / new_visit_id）
  └─ 完成后：结果页显示新 visit，保留旧 visit
```

- 用**新 workspace**，不覆盖原工作区的 `run.log` / `visit.json`；
- 论文/附件复用 `self.files`，重新 `paths.stage_files` 复制；
- 模式、Key、Base、Agent 沿用当前选择；
- 失败时：原报告不变，补充记录标记 `applied=false`，错误显示在流程区；
- 成功后：`supplement.new_visit_id` 回填，界面可切换新旧报告。

## 8. 验收用例

| 场景 | 期望 |
|---|---|
| 报告有 3 个 `expected_data`，补充 1 段 CT 描述 | 新 scenario 的 `inputs_given` 含“报告后补充”；新 visit 生成；`parent_visit_id` 指向旧 visit |
| 补充框为空 / 少于 10 字 | “重新提交分析”禁用 |
| 补充后仍缺 MVI | 新报告继续在 `expected_data` 指出 MVI；不假装已补 |
| 补充文本含“病理确诊 HCC” | 首版只作为资料追加，不自动改疾病；界面提示“如改变诊断请回到场景卡确认” |
| 重跑失败 | 原报告仍可查看/导出；supplement 标记 `applied=false` |
| 旧报告 | 不被覆盖；`runs/` 保留旧 visit；PDF/JSON 仍可导出 |
| Agent 契约 | `visit.schema.json` 无改动；新 visit 仍通过 schema |
| 逐项输入 | “所需资料”在一个只读文本框；每条 `expected_data` 下有一条输入框 |
